Computer Security

2026-10-10 1 min read
  • hardening your system
    • full-disk encryption with a long passphrase (FileVault / LUKS), + a firmware password or secure boot with your own keys
    • FIDO2 hardware keys for login, sudo, and SSH instead of TOTP or SMS
    • egress-aware firewalling per application
      • Little Snitch/LuLu on macOS,
      • OpenSnitch on Linux
    • kernel and userland hardening on Linux: sysctl (kernel.kptr_restrict, kernel.dmesg_restrict, unprivileged user namespaces off where unused), + audit with lynis
    • randomize MAC addresses on untrusted Wi-Fi, and disable Bluetooth and AirDrop discovery when idle
    • compartmentalize high-risk work (Qubes OS, or dedicated VMs per trust level)
    • verify package and release signatures, and prefer reproducible builds where available
  • hardening network access
    • SSH: Ed25519 keys only, PasswordAuthentication no, AllowUsers, and consider fwknop (port knocking) in front of it
    • WireGuard -> remote access rather than exposing services directly
    • encrypted DNS (DoT/DoH) through a resolver you control, with DNSSEC validation
      • why? mitm, cache poisoning
    • monitor Certificate Transparency logs for your own domains (crt.sh, certspotter)
    • disable IPv6 where unused so it can’t bypass your v4 firewall rules

Running Kali Linux Containers on a Linux Server with Docker

2025-06-08 6 min read Tutorial

Kali Linux ships official OCI images under kalilinux/kali-rolling, kalilinux/kali-last-release, and kalilinux/kali-bleeding-edge. They are deliberately minimal, containing little beyond the base userland, so tooling is layered on top through Kali’s metapackages. That makes them well suited to disposable, reproducible assessment environments on a remote server: you get a clean toolchain per engagement, isolated from the host and from each other, without maintaining a full Kali VM. Use them only against systems you are authorized to test.

Set up rootfs of a Debian VM with virtiofsd for Linux Kernel Testing

2025-01-10 13 min read

This post builds a Debian 13 (trixie) rootfs with mmdebstrap, exports it with virtiofsd, boots it under QEMU with a locally built kernel, and arranges for modules, selftests and the kernel tree itself to appear in the guest without any image rebuild step.

Debian is a good fit. Why? because its minimal bootstrap is small, its package set covers nearly every kernel-adjacent tool (linux-perf, bpftool, trace-cmd, stress-ng), and it is the userspace most existing kernel CI tooling, syzkaller included, already assumes.
